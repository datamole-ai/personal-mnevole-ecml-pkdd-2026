### Speaker 1

This is Claude at the University of Vilnius, and I'm pleased to present to you today EXENSAIC, which is an interactive platform for explaining model-unsupervised learning.

 Our development strategy was motivated by systemic sclerosis, which is a rare and severe autoimmune disease. In this context, clinicians are in need for a supervised approach to try to find some partitions and clusters of patient—candidate patients—groups, sorry, with more homogeneous clinical profiles.

 And they are also in need of transparency, reliability, and explicability to understand how these clusters are defined. So, of course, existing environments already provide clustering algorithms or coding libraries and tools to explore explainability metrics.

 EXENSAIC's goal is to first integrate all these components into one and single end-to-end workflow, and second is to help clinicians who are not experts in unsupervised learning and clustering to have tools to help them to interpret the technical outputs of the clustering methodologies. So here you have the end-to-end workflow of EXENSAIC.

 It is composed of 8 modules. The first one is dedicated to user interface.

 EXENSAIC is a streamlined web application-based data exploration, with the user able to download WAI data HTML profile. The second module is dedicated to preprocessing, and EXENSAIC handles missing value imputation, categorical variable encoding, and feature scaling.

 The third module is dedicated to clustering, so the user can choose between 1 up to 10 clustering families and methodologies, ranging from traditional to deep clustering methods. The module generates a comparison table when several methodologies are selected, based on the best silhouette scores.

 Even if there are 3 clustering metrics to investigate, silhouette score can be an avalanche index or a data index. For the explainability, we developed 3 main modules: global, local, and counterfactual.

 I will show them to you in a few seconds. We have a visualization module for the dimensional resolution visualization through PCL, UMAP, and TSME, and also interactive visualization for the clustering and all the explainability modules.

 And an important part of the development was to integrate LLM communication support, because, as I said earlier, clinicians and healthcare practitioners are not familiar, most of them, with the technical outputs of clustering algorithms and methodologies. So the LLM acts as a communication layer, and again, I will show you in a few minutes what it does.

 So if we focus on global explainability, it is important in the clinical perspective of systemic sclerosis, which is, again, a very heterogeneous disease, to understand what are the variables that characterize the clusters. So we implemented a cerebral decision tree and feature permutation to assess these characteristics.

 And for example, as you can see in this radar plot, a clinician would be able to see that the pink—we can see the color very well on the—this is pink. In the pink cluster, we have a biological blood marker that could be associated with a high inflammatory profile, which is correlated to a systemic sclerosis phenotype.

 Or here you have, for example, a more pulmonary or vasculopathic phenotype. So the clinician can assess rapidly how the clusters are defined.

 In the local explainability, the main point for a clinician is to see how well the patient fits into a partition, or how well several patients are similar to each other. Because, again, systemic sclerosis is a highly heterogeneous disease.

 So we implement—sorry, we implement SHAP, LIME, and GMM in this module. And for example, you can see here on the top page features how a specific patient fits its cluster in reference to the cluster center.

 For the counterfactual scenarios, it helps clinicians try to identify if some one or several variables can drive assignment change for a specific patient. And we add the possibility for the user to input several biological constraints.

 So, for example, you have biological range for certain biomarkers, or immutable features like sex, or any features that the clinician would like to be immutable. And for example, we can see on this example that this particular change of magnitude of this particular biomarker could lead to an association with a more inflammatory profile for a patient.

 So in the clinician perspective, it could mean that it would be necessary to reassess the patient management for its clinical care.

 And finally, we implemented the LLM as a communication layer. So the LLM takes as inputs every pattern figure that has been generated by EXENSAIC to generate reports on how to help clinicians to read and assess technical outputs.

 So for now, we are—the user can use an API to use external LLM or a local LLM if the clinician is in possession of such infrastructure. And of course, the clinician remains in control of interpretation, because the LLM only describes the technical outputs.

 So to conclude, EXENSAIC provides an end-to-end and human-in-the-loop environment. And the future work will concentrate on the cluster stability analysis, and particularly in knowledge-guided LLM, because actually, from the release version, we used a general LLM.

 And it would be very interesting for clinicians to add some knowledge-guided solutions to have better clinical evaluation. So thank you for your attention.
